## Решения по спорным местам (можно поменять)
- «Остановка» на тайлах (Поле, Оазис, Госпиталь, Парк) = эффект в конце хода на этом тайле; «Стоп» в Лесу = глоссарий: закончить перемещение или взять монстра.
- Проверка скрытности при входе на тайл с жетонами — только без монстров перед собой (как в правилах). Лазерный дрон / Учёный: жетоны сразу становятся монстрами.
- Атака монстра всегда бьёт владельца; «всех в дальности» — ещё и других игроков (дальняя = до 2 тайлов включая свой).
- Ветеран и Пёс: одиночные атаки распределяются по очереди; урон от тайлов/эффектов — основному персонажу; голод общий, урон от голода — обоим.
- Снижение урона (шлем, жилет…) действует на урон монстров и эффектов, не на яд и голод. Убежище защищает от любого урона в конце хода.
- «Фаланга»: −1 урона роботам, не складывается. Учёный-пришелец: +1 урона пришельцам за каждого учёного в игре.
- Эффект входа монстра срабатывает до Мины приближения.
- Свободный поиск («Открытие») не тратит действие и не считается обыском тайла в этом ходу.
- Многошаговые перемещения (Выносливость, Лошадь, Мотоцикл) дают бесплатные шаги на этот ход.
- Миссия 3: Учёный у первого игрока с начала (подтверждено книгой 2-й ред.). Миссия 9: тоже.
- Миссия 4: еда сдаётся по сумме значений (до 5). Сдавать в любое Убежище.
- Миссия 5: Пыльная книга нужна для обезвреживания; 3 раунда считаются от раунда обезвреживания.
- Миссия 8: старт у фургона; данные или учёный → на Военную базу.
- Миссия 12: перед уничтожением тайла игрок отходит на соседний (из книги 2-й ред.); если кто-то остался на тайле — поражение.
- Все боссы замешиваются после стартовых монстров. Поле — сетка ≈ квадрат, фургон у случайного края (м0/м10 — с противоположной стороны, м6 — в центре).

## Правила (кратко, для движка)
- Ход: 1) бросок 2d6 → маркер монстра на каждый открытый тайл с этим номером (макс. 3 на тайле; если там игрок — он берёт карту монстра); 2) взять карту выжившего (нет карт → смерть); 3) ровно 4 действия; 4) эффекты «конец хода»/«остановка» тайла; 5) голод +1 (6 → истощение: переворот, дальше урон по шкале); 6) атака монстров перед игроком (дальность: иначе только он); 7) проверка победы.
- Действия: шаг на 1 тайл по ортогонали; взять карту; сыграть карту; действие карты; обыск (цвет тайла, 1 раз за ход на тайл).
- Свободно: 1 раз за ход сбросить 2 карты → взять 1; 1 раз за ход обмен находками с игроком на тайле; сдача целей миссии.
- Рука ≤ 10, старт 4 карты + один муллиган до 4. Голод старт 1. Ячейки снаряжения 4, одинаковое снаряжение нельзя (кроме топлива).
- Вход на тайл с маркерами без монстров перед собой: проверка скрытности 2d6 ≤ скрытность − число маркеров, или намеренно забрать монстров. Провал → все маркеры в карты монстров перед собой.
- Дальность: короткая — свой тайл; средняя — свой + ортогональные соседи; дальняя — 1–2 тайла по ортогонали + диагональ, НЕ свой.
- Смерть: монстры игрока в сброс, столько же маркеров на его тайл, его находки остаются на тайле. Поражение: все погибли или кончились маркеры монстров (30). Победа: цель миссии + топливо + все живые у фургона, проверка в конце хода.
- Ветеран и Пёс — один игрок, два персонажа, общий голод, монстров распределить поровну.

## Запуск
- На ПК пользователя PowerShell блокирует `npm.ps1` (ExecutionPolicy) → запускать через `npm.cmd`, например `npm.cmd run dev`.
- `npm run dev` → http://localhost:5173/max-apocalypse/
- `npm run build` → папка `dist/`.

## Боты (MCTS) — src/ai/
- `legal.ts` — `decider(s)` (кто решает: выбор/одолженные действия/ход), `legalActions(s)` — кандидаты ходов, параметры карт через `targets.ts` (до 8 вариантов на карту).
- `evaluate.ts` — `missionScore` (прогресс по каждой из 13 миссий: топливо/предметы сданные и на руках, цели, близость к нужному тайлу, разведка), `evaluate` (0..1: прогресс 0.4, здоровье, живые, голод, угроза монстров, жетоны, колода, вооружённость), `policyStep` — быстрая взвешенная стратегия для прокрутки.
- `mcts.ts` — `think(s, level)`: UCT с детерминизацией (каждый розыгрыш перемешивает колоды и закрытые тайлы — бот не видит будущего), прогрессивное расширение дерева в пределах своего хода, прокрутка до конца хода (сильный — до конца раунда). Уровни: 1 — 0,2 с, 2 — 0,7 с, 3 — 1,8 с на действие.
- `worker.ts` — расчёт в Web Worker; `ui/useBots.ts` — когда решает бот, шлёт состояние в поток и применяет ход с паузой ≥650 мс; без Worker — коротко в основном потоке. Люди не могут нажимать за бота; вопросы бота не показываются людям.
- `PlayerState.bot` (1–3), в `create.players[].bot`. В настройке партии у каждого места выбор «Человек / Бот лёгкий/обычный/сильный».
- Проверка: `npm run bots` (scripts/bot-test.ts: случайные ходы vs быстрая стратегия vs MCTS на миссии). Первые замеры на «Обучении» (2 бота, 60 мс/ход): случайные 0/4, стратегия 0/4, MCTS 1–2/4.
- Замер на 8 партиях «Обучения» (2 бота): 60 мс/ход — 2/8 побед, 200 мс/ход — 3/8 (до исправления зависаний; часть партий не доиграна).

## Фаза 4 — сеть (Firebase) — код готов, ждёт проект Firebase от пользователя
- `npm i firebase@11`. `src/net/firebase.ts` — конфиг из `.env.local` (`VITE_FB_API_KEY/AUTH_DOMAIN/PROJECT_ID/APP_ID`, образец `.env.example`), анонимный вход (`ensureUser`). Без ключей пункт меню показывает, что сеть не настроена.
- `src/net/room.ts` — `coop/<код>` (хост, статус lobby/game, миссия, хардкор, боты, `state` = JSON GameState, версия `v`), `members/<uid>` (имя, персонаж), `actions/<id>` (очередь: uid, JSON действия, clientAt, error). Код комнаты — 5 знаков без похожих букв.
- `src/net/useNetGame.ts` — тот же `GameStore`: хост применяет действия reduce'ом и пишет `state`+`v`; остальные проверяют действие у себя (`tryReduce`) и шлют в очередь; хост разбирает очередь по порядку (`drain`), проверяет «своё место» (`canActFor`: свой персонаж; хост — ещё боты), отказ пишет в `error` действия → у отправителя тост. Старые снимки (меньшая `v`) не затирают свежие.
- `src/ui/NetPlay.tsx` (грузится лениво, отдельный чанк) — вход (имя, персонаж) → «Создать комнату» / «Войти по коду» → лобби (код, участники 👑, свои персонажи, боты хоста с уровнем, миссия, хардкор, «Начать») → `Game` с `net` (боты только у хоста; вопросы — только своему игроку; код комнаты в шапке; подготовка — каждый меняет свои карты одновременно, первого выбирает хост). Комната запоминается (localStorage `ma-net-room`) — после перезагрузки возвращаемся в неё.
- `firestore.rules` — правила доступа (комнату меняет только хост, участник пишет только себя, действия — от своего имени).
- Ограничения: если хост закрыл приложение, партия ждёт его возвращения (передачи хоста пока нет). Старые комнаты не удаляются.
- СДЕЛАНО (Claude в браузере): проект Firebase `max-apocalypse` (без Gemini и Analytics), Anonymous auth включён, Firestore Standard в `eur3` (production mode), правила из `firestore.rules` опубликованы, веб-приложение `max-apocalypse-web` зарегистрировано, конфиг в `.env.local` и `.env.production`. Проверка `node --env-file=.env.local scripts/net-check.ts` — два анонимных игрока, комната, ход, запреты правил — всё OK.

- Ставятся git и GitHub CLI (winget). Нужен вход пользователя: GitHub (gh auth login) и Telegram Web (QR).

### Что сделать пользователю (один раз)
1. https://console.firebase.google.com → «Создать проект» (Google Analytics можно выключить).
2. Build → Authentication → Get started → Sign-in method → Anonymous → Enable.
3. Build → Firestore Database → Create database → регион (например, eur3) → «Production mode».
4. Firestore → Rules → вставить содержимое `firestore.rules` → Publish.
5. Project settings (шестерёнка) → General → Your apps → «</>» (Web) → любое имя, без Hosting → скопировать `apiKey`, `authDomain`, `projectId`, `appId` в `.env.local` по образцу `.env.example` (или прислать их в чат).
6. Перезапустить `npm.cmd run dev`.
